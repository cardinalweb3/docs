Cardinal support works best when you start with self-service resources. Most integration and pilot issues can be resolved by checking the documentation, reviewing the diagnostic checklist, and examining the `request_id` and `findings` in the API response. When you do need to contact the team, the guidance below helps you prepare a clear, safe request that gets to resolution faster.

<Warning>
  Never send API keys, private keys, seed phrases, passwords, full authentication tokens, identity documents, confidential contracts, or unrestricted transaction records in any support communication.
</Warning>

## Choose the right route

| Request type | First action | What to include |
|---|---|---|
| Integration help | Check the integration guide and FAQ | Environment, relevant code sample, error message and `request_id` |
| Unexpected decision | Check the `findings` array in the response | `request_id`, non-secret intent JSON, decision received, expected result |
| API error | Check the product status and errors reference | HTTP status code, response body, `request_id` |
| Security incident | Follow your incident-response process immediately | Sanitised description, timeline, affected environment, containment steps |
| Pilot inquiry | Contact Cardinal directly | Organisation name, use case, target network and asset, timeline |

## Severity guide

| Severity | Use when |
|---|---|
| **Critical** | Active security issue, unauthorised settlement, exposed credentials, or an unsafe transaction flow |
| **High** | A pilot or protected transaction is blocked, or a severe integration failure is recurring |
| **Normal** | A functional issue exists but a safe workaround is available |
| **General** | How-to, documentation, product, pilot-planning, or commercial question |

Severity helps Cardinal understand impact. It does not create a guaranteed response time outside an applicable agreement.

## Diagnostic checklist

Run through these steps before submitting a request:

- [ ] Confirm the product and environment
- [ ] Confirm the network, token, contract, wallet, and address role
- [ ] Verify the final canonical transaction intent
- [ ] Record the Cardinal `request_id`, if returned
- [ ] Record your internal reference and approximate timestamp
- [ ] Capture the HTTP response status and non-secret error
- [ ] Check whether the issue is reproducible
- [ ] Check for a pending API request or blockchain transaction
- [ ] Remove all secrets, personal data, and confidential records from your evidence
- [ ] Pause the affected flow if transaction safety is uncertain

## What Cardinal support will never ask for

If you receive a request for any of the following, stop immediately and verify using the published contact details on this page:

- A private key or seed phrase
- A password or full authentication token
- API keys in plain text
- Remote signing authority
- A transfer to a personal wallet
- Identity documents through an unapproved channel
- A confidential contract outside an authorised commercial process

## Security incidents

If you suspect a security incident:

<Steps>
  <Step title="Pause the affected flow">
    Stop the impacted transaction or integration flow immediately to prevent further exposure.
  </Step>
  <Step title="Rotate exposed credentials">
    Rotate any Cardinal and partner credentials that may have been compromised. Revoke or restrict affected sessions and permissions.
  </Step>
  <Step title="Preserve evidence">
    Save sanitised logs, timestamps, `request_id` values, intent hashes, and public transaction references. Do not send live credentials or identity documents as evidence.
  </Step>
  <Step title="Follow your incident-response process">
    Execute your organisation's internal incident-response and notification procedures, then contact Cardinal through the agreed escalation route or the contact details above.
  </Step>
</Steps>

## SafeSend and Escrow support boundaries

SafeSend's currently verified scope is a controlled Arbitrum Sepolia testnet MVP. Programmable Escrow remains in final testing and security hardening. Confirm the approved deployment, network, contract address, roles, value limits, and operational process before testing.

Cardinal support cannot bypass smart-contract roles or state transitions, reverse a final blockchain transaction, recover private keys, determine legal ownership, or replace a licensed escrow provider.
