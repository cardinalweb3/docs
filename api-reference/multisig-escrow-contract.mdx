The Cardinal Multisig Escrow contract provides ERC-20 settlement for higher-value transactions where fund release requires a configurable number of authorised approvers to sign off. The buyer locks tokens at creation, the seller accepts, and then a set of wallets holding the `APPROVER_ROLE` each cast one approval vote. Once the number of approvals reaches the global release threshold, anyone can trigger the actual settlement. There is no dispute resolution mechanism and no release window timeout — release is entirely approval-gated.

<Warning>
  The Multisig Escrow contract is in **final testing** and has not been externally audited. It is not approved for unrestricted mainnet use. Cardinal will publish verified deployment details, role owners, and security review status before any production launch.
</Warning>

## Participants

| Participant | Contract authority                                                          |
| ----------- | --------------------------------------------------------------------------- |
| Buyer       | Creates and funds the escrow; refunds before seller acceptance              |
| Seller      | Accepts the escrow before the acceptance deadline                           |
| Approvers   | Wallets holding `APPROVER_ROLE`; each casts one approval vote per escrow    |

<Note>
  The approver set and release threshold are **global** — they apply to every escrow in the contract. There is no per-escrow approval panel or milestone-based policy. Do not describe this contract as supporting buyer-selected approvers or per-escrow custom policies.
</Note>

## Lifecycle states

| Status      | Value | Meaning                                                    |
| ----------- | :---: | ---------------------------------------------------------- |
| `None`      |   0   | No escrow exists for this ID                               |
| `Created`   |   1   | Buyer funds are locked; seller acceptance pending          |
| `Accepted`  |   2   | Seller accepted; approvers may now cast votes              |
| `Released`  |   3   | Approval threshold met; seller and fee recipient were paid |
| `Refunded`  |   4   | Full amount returned to the buyer                          |

**State transitions:**

```
Created ──→ Accepted ──→ (threshold met) ──→ Released
   └──────→ Refunded
```

`Released` and `Refunded` are terminal states. There is no `Disputed` state in Multisig Escrow.

## Key invariant

The number of active approvers must always be **greater than or equal to** the release threshold. The contract enforces this at every point where an approver could be removed: revoking an approver role, renouncing it, or reducing the threshold. This prevents the contract from reaching a state where the threshold can never be met.

## Fees

The platform fee is charged only on settlement to the seller. A buyer refund returns the full locked amount with no fee deducted.

```
feeAmount = amount × feeBps ÷ 10,000
```

The default fee is **2.5% (250 basis points)**. Read the verified deployment configuration for the active rate.

## Functions

### createMultisigEscrow

```solidity
function createMultisigEscrow(
    address seller,
    address token,
    uint256 amount,
    uint256 acceptanceDeadline
) external returns (uint256 escrowId)
```

Creates a new multisig-gated escrow and immediately transfers the full `amount` from your wallet into the contract. The platform fee is calculated and stored at creation time.

**Caller:** Buyer

<ParamField path="seller" type="address" required>
  Wallet address of the counterparty who must accept. Must be non-zero.
</ParamField>

<ParamField path="token" type="address" required>
  ERC-20 token contract address. Must be non-zero.
</ParamField>

<ParamField path="amount" type="uint256" required>
  Total token amount to lock. Must be greater than zero. Approve this exact amount before calling.
</ParamField>

<ParamField path="acceptanceDeadline" type="uint256" required>
  Unix timestamp by which the seller must accept. Must be strictly greater than the current block timestamp.
</ParamField>

**Returns:** `escrowId` — store this to reference the escrow in all subsequent calls.

**Emits:** `MultisigEscrowCreated`

---

### acceptMultisigEscrow

```solidity
function acceptMultisigEscrow(uint256 escrowId) external
```

Accepts the escrow terms. Only the recorded seller can call this, and only on or before `acceptanceDeadline`. Once accepted, the escrow moves to `Accepted` status and approvers can begin voting.

**Caller:** Seller only

<ParamField path="escrowId" type="uint256" required>
  ID of the escrow to accept. Must be in `Created` status and within the acceptance deadline.
</ParamField>

**Emits:** `MultisigEscrowAccepted`

---

### approveRelease

```solidity
function approveRelease(uint256 escrowId) external
```

Casts one approval vote for releasing the escrow. Each approver may vote exactly once per escrow — a second call from the same address reverts with `ReleaseAlreadyApproved`. The event emitted includes the running approval count and the current threshold so listeners can track progress toward release.

**Caller:** Wallets holding `APPROVER_ROLE` only

<ParamField path="escrowId" type="uint256" required>
  ID of the accepted escrow to approve. Must be in `Accepted` status.
</ParamField>

**Emits:** `ReleaseApproved` (includes `approvalCount` and `threshold`)

---

### releaseMultisigEscrow

```solidity
function releaseMultisigEscrow(uint256 escrowId) external
```

Transfers the settlement amount to the seller and the platform fee to the fee recipient. This function is permissionless — anyone can call it once the approval threshold has been reached. This design lets the buyer, seller, or an automation service trigger final settlement without any of them holding special authority over fund destination.

**Caller:** Anyone (permissionless once threshold is met)

<ParamField path="escrowId" type="uint256" required>
  ID of the accepted escrow to release. Must be in `Accepted` status with `approvalCount ≥ releaseThreshold`.
</ParamField>

**Emits:** `MultisigEscrowReleased`

---

### refundMultisigEscrow

```solidity
function refundMultisigEscrow(uint256 escrowId) external
```

Returns the full locked amount to the buyer with no platform fee. Only available before the seller accepts — there is no post-acceptance refund path in Multisig Escrow.

**Caller:** Buyer only

<ParamField path="escrowId" type="uint256" required>
  ID of the escrow to refund. Must be in `Created` status.
</ParamField>

**Emits:** `MultisigEscrowRefunded`

---

### getMultisigEscrow

```solidity
function getMultisigEscrow(uint256 escrowId) external view returns (MultisigEscrowTransaction memory)
```

Returns the full on-chain record for an escrow. Use this as the source of truth for status, approval count, and available actions.

**Caller:** Anyone (view function, no gas cost)

<ParamField path="escrowId" type="uint256" required>
  ID of the escrow to read.
</ParamField>

**Returns:** A `MultisigEscrowTransaction` struct:

| Field                | Type                      | Description                                          |
| -------------------- | ------------------------- | ---------------------------------------------------- |
| `buyer`              | `address`                 | Wallet that created and funded the escrow            |
| `seller`             | `address`                 | Counterparty accepting and receiving settlement      |
| `token`              | `address`                 | ERC-20 token locked by the contract                  |
| `amount`             | `uint256`                 | Total amount locked                                  |
| `feeAmount`          | `uint256`                 | Platform fee recorded at creation time               |
| `acceptanceDeadline` | `uint256`                 | Latest timestamp for seller acceptance               |
| `approvalCount`      | `uint256`                 | Number of approver votes cast so far                 |
| `status`             | `MultisigEscrowStatus`    | Current lifecycle state (see statuses above)         |

---

### hasApprovedRelease

```solidity
function hasApprovedRelease(uint256 escrowId, address approver) external view returns (bool)
```

Checks whether a specific approver has already cast their vote for a given escrow. Use this to build approval-status UIs and avoid submitting a transaction that would revert with `ReleaseAlreadyApproved`.

**Caller:** Anyone (view function, no gas cost)

<ParamField path="escrowId" type="uint256" required>
  ID of the escrow to check.
</ParamField>

<ParamField path="approver" type="address" required>
  Wallet address of the approver to query.
</ParamField>

**Returns:** `true` if this approver has already voted to release this escrow, `false` otherwise.

---

### previewFee

```solidity
function previewFee(uint256 amount) external view returns (uint256 feeAmount)
```

Returns the platform fee that would be charged on settlement for a given amount.

**Caller:** Anyone (view function, no gas cost)

<ParamField path="amount" type="uint256" required>
  The total token amount you plan to lock.
</ParamField>

**Returns:** `feeAmount` — the token amount deducted from the settlement on release.

## Events

| Event                      | Parameters                                                                               | When emitted                               |
| -------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------ |
| `MultisigEscrowCreated`    | `escrowId`, `buyer`, `seller`, `token`, `amount`, `feeAmount`, `acceptanceDeadline`      | Buyer funds a new escrow                   |
| `MultisigEscrowAccepted`   | `escrowId`, `seller`                                                                     | Seller accepts                             |
| `ReleaseApproved`          | `escrowId`, `approver`, `approvalCount`, `threshold`                                     | An approver casts one vote                 |
| `MultisigEscrowReleased`   | `escrowId`, `seller`, `sellerAmount`, `feeAmount`                                        | Threshold met; seller settlement completed |
| `MultisigEscrowRefunded`   | `escrowId`, `buyer`, `amount`                                                            | Funds returned to buyer                    |
| `ReleaseThresholdUpdated`  | `previousThreshold`, `newThreshold`                                                      | Global release threshold changed           |
| `FeeConfigUpdated`         | `feeRecipient`, `feeBps`                                                                 | Fee configuration changed                  |
| `OwnershipTransferred`     | `previousAdmin`, `newAdmin`                                                              | Administrative ownership transferred       |

## Ethers.js example

The example below shows the full approver-driven release flow: check approval status, cast a vote with `approveRelease`, monitor votes across multiple approvers, and trigger `releaseMultisigEscrow` once the threshold is met.

```typescript
import { ethers } from 'ethers';

const MULTISIG_ESCROW_ABI = [
  'function createMultisigEscrow(address seller, address token, uint256 amount, uint256 acceptanceDeadline) returns (uint256)',
  'function acceptMultisigEscrow(uint256 escrowId)',
  'function approveRelease(uint256 escrowId)',
  'function releaseMultisigEscrow(uint256 escrowId)',
  'function refundMultisigEscrow(uint256 escrowId)',
  'function getMultisigEscrow(uint256 escrowId) view returns (tuple(address buyer, address seller, address token, uint256 amount, uint256 feeAmount, uint256 acceptanceDeadline, uint256 approvalCount, uint8 status))',
  'function hasApprovedRelease(uint256 escrowId, address approver) view returns (bool)',
  'function previewFee(uint256 amount) view returns (uint256)',
  // Read the global threshold (public state variable)
  'function _releaseThreshold() view returns (uint256)',
  // Events for monitoring
  'event ReleaseApproved(uint256 indexed escrowId, address indexed approver, uint256 approvalCount, uint256 threshold)',
];

const ERC20_ABI = [
  'function approve(address spender, uint256 amount) returns (bool)',
];

const provider = new ethers.BrowserProvider(window.ethereum);
const signer = await provider.getSigner();

const multisigEscrow = new ethers.Contract(
  MULTISIG_ESCROW_ADDRESS,
  MULTISIG_ESCROW_ABI,
  signer
);
const token = new ethers.Contract(TOKEN_ADDRESS, ERC20_ABI, signer);

const escrowId = 42n; // ID of a previously created and accepted escrow

// Check how many approvals are still needed
const escrow = await multisigEscrow.getMultisigEscrow(escrowId);
const threshold = await multisigEscrow._releaseThreshold();
const remaining = threshold - escrow.approvalCount;
console.log(
  `Approvals so far: ${escrow.approvalCount} / ${threshold} (${remaining} more needed)`
);

// Check whether this signer has already voted
const signerAddress = await signer.getAddress();
const alreadyVoted = await multisigEscrow.hasApprovedRelease(escrowId, signerAddress);

if (!alreadyVoted) {
  // Cast this approver's vote
  const approveTx = await multisigEscrow.approveRelease(escrowId);
  const approveReceipt = await approveTx.wait();

  // Parse the ReleaseApproved event to show updated progress
  const iface = new ethers.Interface(MULTISIG_ESCROW_ABI);
  const approveEvent = approveReceipt.logs
    .map((log) => { try { return iface.parseLog(log); } catch { return null; } })
    .find((e) => e?.name === 'ReleaseApproved');

  if (approveEvent) {
    const { approvalCount, threshold: eventThreshold } = approveEvent.args;
    console.log(`Vote cast. Approvals now: ${approvalCount} / ${eventThreshold}`);
  }
} else {
  console.log('This approver has already voted for this escrow.');
}

// Once the threshold is met, anyone can trigger the release (permissionless)
const updated = await multisigEscrow.getMultisigEscrow(escrowId);
if (updated.approvalCount >= threshold) {
  const releaseTx = await multisigEscrow.releaseMultisigEscrow(escrowId);
  await releaseTx.wait();
  console.log('Escrow released to seller.');
}
```
